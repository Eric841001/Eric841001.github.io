Executive Summary​

Zero Trust is not a single product implementation.

It is an enterprise security architecture based on continuous verification, least privilege access, device trust, data protection and security monitoring.

For Microsoft cloud environments, Zero Trust should be designed across Microsoft Entra ID, Conditional Access, Intune, Defender, Purview and Microsoft 365 workloads.

Zero Trust Reference Architecture

Verify access, protect data and operate response continuously

Zero Trust becomes practical when identity, device trust, Conditional Access, Defender, Purview, Microsoft 365 workloads and operations evidence are designed together.
VerifyLimitProtectRespond
Security Control PlaneIdentity to operations evidence
01IdentityEnforce MFA, Conditional Access, privileged access and guest lifecycle controls.02DeviceUse Intune compliance, security baseline and Defender for Endpoint signals.03DataClassify, label, retain and protect information with Microsoft Purview.04OperateCorrelate incidents, tune alerts, define response process and review evidence.
Zero Trust ruleDo not treat Zero Trust as a product rollout. Treat it as a phased control and evidence operating model.

Zero Trust Principles​

PrincipleDescription
Verify ExplicitlyAlways authenticate and authorize based on available signals
Use Least PrivilegeLimit user and administrator access to the minimum required
Assume Compromise (formerly Assume Breach)Design detection, response, containment and recovery capabilities

Microsoft’s current Zero Trust principles use Assume compromise, previously called Assume breach. The principle includes limiting impact and preparing detection, response and recovery.

Before implementing Zero Trust, leadership should confirm:

Frequently Asked Questions​

What is the practical starting point for Zero Trust?​

Start with identity and device trust. MFA, legacy authentication blocking, Conditional Access, privileged access and device compliance create the foundation for the rest of the program.

Is Zero Trust a single project?​

No. Zero Trust is an operating model. It should be implemented in phases across identity, endpoint, data, threat protection, application access and governance.

How does Zero Trust support Copilot and AI adoption?​

Microsoft 365 Copilot respects the current user’s permissions when accessing organizational data. Individual agents also require review of their authentication, connected resources and permissions; they do not all inherit the same Microsoft 365 access boundary. Copilot Studio supports unauthenticated agents as well as authenticated configurations. See Copilot data access and agent authentication options.

What should executives approve?​

Executives should approve target maturity, risk tolerance, device scope, external sharing posture, monitoring model, licensing assumptions and phased roadmap.
