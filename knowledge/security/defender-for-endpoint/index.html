ENDPOINT SECURITY OPERATIONS

Turn endpoint telemetry into trusted access decisions

Microsoft Defender for Endpoint should be designed as the device signal layer for Zero Trust, Defender XDR and Copilot readiness. The outcome is not only malware protection. The outcome is trusted device posture, incident evidence, vulnerability visibility and response ownership.

Defender XDRConditional AccessDetection Validation
Endpoint LoopSignal ready
01OnboardWindows, macOS, Linux, servers and privileged devices.02ControlASR, tamper protection, device groups and security baselines.03OperateAlerts, device timeline, vulnerability backlog and response.04ImproveCoverage, exceptions, test evidence and executive reporting.
Endpoint risk is a business signalDevice risk should influence administrator access, Copilot readiness, privileged operations and incident response, not sit isolated in an endpoint console.

Executive Summary​

Microsoft Defender for Endpoint provides endpoint detection and response, attack surface reduction, vulnerability management and endpoint security telemetry.

EDR and automated investigation are Plan 2 capabilities; verify the Defender plan requirements and server licensing separately. The ASR rules discussed below target Windows. Do not apply the same feature checklist to macOS or Linux without checking platform support. In enterprise Microsoft 365 programs, it becomes a control input for Defender XDR, Microsoft Intune, Microsoft Entra Conditional Access and security operations.

The strongest deployment pattern is to design Defender for Endpoint as an operating model: who owns device onboarding, who approves exceptions, how ASR rules move from audit to block, how incidents are escalated, and how endpoint risk affects access decisions.

한국어 요약​

Defender for Endpoint로 기기의 위협과 취약점을 확인하고 대응하는 절차를 정리했습니다.

Defender XDR, Intune과 Conditional Access를 연결할 때는 기기별 지원 기능과 위험 신호, 정책 적용 결과를 확인하세요.

Linux·macOS의 10월 운영 변경​

Amazon Linux 2 ARM64의 Defender 지원은 2026년 10월 31일 종료됐습니다. Linux 데스크톱 지원은 Public Preview이며, 데스크톱용 P2 권한과 서버용 라이선스를 구분해야 합니다. Linux 온보딩 가이드에서 종료 대상과 10월 빌드의 순차 적용 조건을 확인하세요.

macOS의 10월 추가 GA 빌드 101.26092.0009에는 Device Control v1 종료, 보호·시스템 확장 상태 보고와 EDR 개선이 포함됩니다. USB 제어 전환 안내에서 v2 구성과 권한·실제 적용 결과를 확인하세요. macOS 온보딩 가이드에서 설치 버전과 권한 점검 방법을 확인하세요. 근거는 Microsoft 릴리스와 Linux 지원·라이선스 조건입니다.

Microsoft Store 앱의 취약점 확인​

2026년 10월부터 Microsoft Store로 설치한 앱의 취약점 평가가 정식 제공됩니다. 현재 지원 대상은 일부 자주 사용되는 앱으로 제한됩니다. 목록에 표시되거나 취약점이 발견되지 않았다는 이유만으로 모든 앱의 안전성을 판단해서는 안 됩니다.

Defender 포털의 소프트웨어 목록에서 앱을 열고 Software evidence의 Microsoft Store 표시, 앱 버전과 파일 위치를 확인하세요. 함께 제공되는 쿼리로 영향을 받는 앱을 조사할 수 있습니다. 버전 관리는 Microsoft Store에서 진행하고, 표시된 WindowsApps 경로의 파일을 직접 수정하거나 삭제하지 마세요.

근거: Defender for Endpoint 10월 변경 사항, Microsoft Store 앱의 취약점 평가 범위와 확인 방법.

How device risk reaches Conditional Access​

For device-based access control, connect Defender for Endpoint to Intune, onboard the devices and assign an Intune compliance policy with a machine-risk threshold. Conditional Access then requires the device to be marked as compliant; onboarding alone does not create that access policy. This documented risk-based compliance workflow supports Windows, Android and iOS/iPadOS. Do not assume that macOS or Linux onboarding provides the same compliance integration. See integration and supported platforms.

ASR 적용 전 확인할 조건​

ASR 규칙을 적용할 Windows 기기에서는 Microsoft Defender Antivirus가 활성 모드로 실행되어야 합니다. 수동 모드에 EDR 차단 모드를 더해도 이 조건을 대신하지 못합니다. 규칙별 클라우드 보호 요구 사항과 백신 구성 요소 버전도 확인하세요.

Warn 모드의 Unblock은 영구 예외가 아닌 24시간 임시 해제입니다. 플랫폼 4.18.26060부터는 해제에 관리자 승인이 필요합니다. 모든 규칙과 관리 도구가 Warn 모드를 지원하는 것은 아니므로, 파일럿에서 해당 규칙의 지원 여부와 승인 절차를 함께 시험하세요. 지속적인 예외가 필요하면 규칙별 제외 설정을 검토합니다.

근거: ASR 요구 사항과 모드별 동작.

Deployment Journey​

Audit behavior depends on the control. For example, web content filtering can collect category activity with no categories selected for blocking; its Network Protection prerequisites still apply. This is different from turning every web-protection component to audit mode.

Deployment JourneyAudit first, then enforce
01ScopeConfirm device types, ownership, privileged endpoints, exclusions and onboarding method.
02PilotOnboard a controlled pilot group and validate sensor health, inventory and alerts.
03AuditUse supported audit settings for selected controls; validate platform behavior and existing blocking policies before rollout.
04EnforceMove rules into block mode by ring, workload sensitivity and exception maturity.
05OperateTrack alerts, vulnerability backlog, exceptions, device risk and response actions.

Common Mistakes​

  • Treating Defender for Endpoint as only antivirus replacement.
  • Enforcing ASR rules without audit results and exception ownership.
  • Onboarding devices without validating sensor health and alert generation.
  • Ignoring macOS, Linux and server coverage while reporting broad endpoint readiness.
  • Connecting device risk to Conditional Access before helpdesk and rollback processes are ready.
  • Reporting exposure score without a remediation owner and executive review cadence.

로컬 AI 에이전트 검색​

Windows·macOS의 지원 대상 로컬 AI 에이전트와 구성된 MCP 서버 검색은 정식 제공됩니다. WSL 검색과 일부 macOS VS Code 확장 목록 수집은 미리 보기이므로 지원 표를 구분해서 확인하세요.

상용 클라우드, Defender for Endpoint P2, 기기 온보딩이 필요합니다. 최소 버전은 Windows 백신 플랫폼 4.18.26090.9, macOS 101.26072.0017입니다. 원칙적으로 백신 활성 모드와 실시간 보호가 필요하며, 지원 표에 명시된 VS Code 확장 목록 수집에는 예외가 있습니다. 이 예외가 MCP 구성 검색이나 런타임 보호까지 허용한다는 뜻은 아닙니다.

P2로 목록과 Advanced Hunting을 조회할 수 있지만, 위험 수준·위험 지표·보안 권고에는 Microsoft 365 E7 또는 Agent 365와 P2의 조합이 필요합니다. 프로세스가 실행된 사실만으로 발견될 수 있으므로 목록에 있다는 이유만으로 실제 서비스 사용이나 접근 성공을 단정하지 마세요.
