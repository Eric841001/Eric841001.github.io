Data Loss Prevention

PURVIEW DLP CONTROL MODEL

Protect sensitive work without breaking business flow

DLP succeeds when protected data, policy mode, user coaching, exception approval and alert tuning are treated as one adoption journey.

DataScope
PolicyMode
UserCoaching
AuditEvidence

Executive Summary​

Data Loss Prevention helps organizations prevent sensitive information from being shared through inappropriate channels such as email, Teams, SharePoint, OneDrive, endpoint copy actions or external collaboration.

DLP should be designed as a business control, not only a security rule. The strongest programs combine sensitive information types, user coaching, exception workflow and measurable policy tuning.

Business Scenario​

  • Prevent accidental sharing of personal, financial or contractual data
  • Control external sharing from SharePoint and OneDrive
  • Reduce data leakage risk before Copilot adoption
  • Establish evidence for audit and compliance
  • Govern endpoint copy, print and upload behavior

Architecture​

DLP adoption loopAudit before enforcement
01Classify dataMap sensitive information types, trainable classifiers and business-owned data categories.
02Design policySeparate workload scope, conditions, user groups, unmanaged device rules and policy tips.
03Tune impactStart in simulation mode, review false positives and tune thresholds before enforcement.
04Operate exceptionsUse named reviewers, time-bound exceptions, alert evidence and Copilot data protection reporting.

Implementation​

  1. Define protected data categories with business owners.
  2. Select sensitive information types and trainable classifiers where needed.
  3. Start with simulation mode; use Audit only when testing a supported endpoint activity action.
  4. Review false positives and tune thresholds.
  5. Move high-confidence scenarios to warning or block.
  6. Define exception request and approval process.

FTP·SFTP 전송과 네트워크 보호​

Microsoft는 2026년 10월 Endpoint DLP의 FTP·SFTP 전송 보호를 일반 공급으로 안내했습니다. Purview에 온보딩한 Windows 기기에서 Devices 위치의 정책에 FTP and SFTP transfers 활동을 추가합니다. 소수 사용자를 Audit only로 먼저 운영하고 Activity explorer의 전송 기록을 확인한 뒤 차단 여부를 정하세요. 설정 절차와 권한을 확인합니다.

네트워크 DLP와 Endpoint DLP는 적용 경로가 다릅니다. Entra Global Secure Access 연동에는 Microsoft 365 E7 또는 Purview E5 상당의 사용권과 Entra Internet Access 상당의 사용권 조합이 필요합니다. 다른 SASE·보안 브라우저 연동에는 Purview E5 상당의 사용권과 Purview 종량제 설정이 필요하며, B2B 게스트는 네트워크 보호 정책 대상에서 제외됩니다. 연동별 라이선스와 제한을 확인하고 실제 전송 경로를 시험하세요.

외부 조직과의 Teams 대화​

Teams의 공유 채널과 외부 액세스 채팅은 DLP 적용 방식이 다릅니다. 공유 채널에서는 각 발신자의 소속 테넌트 정책으로 메시지를 평가합니다. 외부 액세스 채팅에서는 대화를 시작한 테넌트가 호스트이며, 그 호스트에 소속된 사용자의 메시지에 호스트 정책을 적용합니다. 다른 테넌트 사용자의 메시지까지 호스트 정책으로 검사하거나, 사용자 소속 테넌트의 정책이 외부 호스트 대화에도 자동으로 따라간다고 가정하지 마세요.

시험할 때는 채팅을 시작하는 조직을 바꾸고 양쪽 사용자가 보낸 메시지의 처리 결과를 확인하세요. 공유 파일은 저장된 SharePoint·OneDrive 위치에 적용되는 정책도 따로 점검합니다. Teams 대화별 DLP 적용 범위를 참고하세요.

macOS 27 권한과 운영 시 주의할 점​

Microsoft는 macOS 27의 Endpoint DLP 권한 변경을 미리 보기로 안내합니다. 클라이언트는 101.26072 이상이어야 하며, 설정 > 개인정보 보호 및 보안 > Device Control and Data Access 권한을 확인하세요. MDM으로 배포한 뒤에도 사용자가 이 권한을 끌 수 있습니다. 이때 Safari·Chrome·Firefox의 URL과 브라우저 정보를 가져오지 못하므로 권한 상태와 복구 알림을 함께 관리해야 합니다.

권한이 없을 때 적용할 업로드 보호와 브라우저 붙여넣기 보호는 각각 설정합니다. 두 설정의 기본값은 Enforce이며 Audit에서는 기록만 남기고 추가 제한을 적용하지 않습니다. 시험 목적으로 Audit를 사용한다면 보호 공백을 고려하고 권한 복구 여부를 확인하세요. macOS 27 설정과 보호 모드에 자세한 조건이 있습니다.

  • Windows와 macOS의 앱 제어 차이: 제한된 앱 목록이나 규칙에 추가한 제한된 앱 그룹에 속하지 않는 앱의 접근 제어는 Windows에서 지원하지만 macOS에서는 지원하지 않습니다. 같은 규칙을 배포해도 보호 범위가 같다고 가정하지 마세요. 운영체제별 지원 표를 확인하세요.
  • Exchange의 필수 레이블 지정: 민감도 레이블 조건과 정책 팁을 사용하는 DLP 정책에서 필수 레이블 지정 창으로 레이블을 선택하면 정책 팁을 다시 평가하지 않습니다. 팁이 표시되지 않아도 설정한 DLP 동작은 적용됩니다. 경고 표시와 실제 전송 결과를 나누어 시험하세요. 레이블 조건과 정책 팁을 참고하세요.

Licensing​

Advanced DLP across Microsoft 365 workloads and endpoints may require higher compliance licensing. Confirm workload coverage before committing policy scope in a proposal.

Security​

  • Use separate policies for high-risk and medium-risk data.
  • Apply stricter controls to unmanaged devices and external recipients.
  • Route alerts to a named review owner.
  • Keep policy exceptions time-bound and auditable.

Decision Checklist​

DecisionRecommended Question
Data scopeWhich sensitive data categories require DLP protection?
Workload scopeShould policies cover Exchange, Teams, SharePoint, OneDrive and endpoint?
Enforcement modeWhich scenarios start in audit, warn or block mode?
Exception modelWho approves temporary exceptions and how are they reviewed?
User coachingWhat policy tip explains the business reason to users?
Alert reviewWho reviews DLP alerts and tunes false positives?

Anti-Patterns​

  • Starting with broad block policies before audit evidence exists
  • Designing DLP without business data owners
  • Ignoring user education and policy tips
  • Treating false positives as a reason to abandon DLP instead of tuning
  • Separating DLP design from Copilot data protection planning

Delivery Artifacts​

  • DLP policy design matrix
  • Sensitive information type mapping
  • Endpoint DLP scenario plan
  • Exception and approval workflow
  • Alert review and tuning runbook
  • Copilot data protection readiness summary

Frequently Asked Questions​

Should DLP start in block mode?​

Usually no. Start with simulation mode for priority scenarios, review false positives and user impact, then enable the supported warning or blocking actions.

How does DLP relate to Copilot?​

Copilot can surface content that users already have access to. DLP helps reduce accidental sharing and exfiltration risk, while Purview labels and permission cleanup help define safer data boundaries.

What makes a DLP policy usable?​

A usable DLP policy has a clear data owner, meaningful condition logic, user coaching text, exception process, alert owner and tuning cadence.

What evidence should be captured?​

Capture policy scope, test results, false positive review, exception approvals, alert triage records and final enforcement decision.

Customer Success Pattern​

IndustryScenarioPattern
Financial ServicesCustomer data protectionAudit-first rollout, high-confidence block policy and exception workflow
ManufacturingIntellectual property protectionEndpoint DLP and SharePoint external sharing review

Lessons Learned​

Explain the protected data and expected user actions before enforcing a policy. Use pilot results, policy tips and support feedback to adjust the rollout and measure its impact.
