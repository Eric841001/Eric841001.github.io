Copilot Studio 2026 플랫폼 변경

Copilot 모델·기능 안내

GPT-6.2 Sol·Astra · 순차 배포의 앱별 제공 조건과 기능별 변경 내용을 확인할 수 있습니다. 공식 원문 확인: 2026-11-25.

2026 Agent Platform Baseline

Copilot Studio is now an enterprise agent platform, not just a chatbot builder

The 2026 planning baseline should treat every agent as an operational object with identity, owner, knowledge boundary, reusable skills, workflow actions, cost forecasting, evaluation and retirement rules.

AI Agent FactoryOperating ModelRequest Agent Assets
Platform ShiftGoverned agents
01BuildNew agent experience, Work IQ, skills, memory and workflows.02ExecuteComputer use, agent flows, connectors, APIs and agent-to-agent scenarios.03GovernInventory, readiness status, Entra Agent IDs, DLP, analytics and evaluations.04OperateCost forecasting, owner review, telemetry, retirement and continuous improvement.
Do not build agents faster than governance can absorbThe practical goal is not to create many agents. The goal is to create a repeatable system for approving, publishing, monitoring and retiring agents.

Executive Summary​

Copilot Studio has moved beyond chatbot authoring. In 2026, it should be positioned as an enterprise agent platform that combines low-code agent design, workflow automation, Microsoft 365 grounding, reusable skills, computer use, agent-to-agent connectivity and governance telemetry.

The design shift is simple but important: an agent is no longer just a conversational interface. It is an operational object that needs identity, ownership, knowledge boundaries, tools, cost forecasting, monitoring and retirement rules.

한국어 요약​

2026년 Copilot Studio의 에이전트, 워크플로와 실행 환경 변경을 정리했습니다. 기능마다 정식 제공 여부와 적용 조건이 다르므로 본문의 발표일과 공식 자료를 함께 확인하세요.

구축 전에 에이전트 담당자, 접근할 자료, 실행할 도구, 승인 절차와 비용 한도를 정합니다.

Copilot, Copilot Studio, M365 Agents와 Copilot Cowork는 맡길 업무에 맞춰 선택합니다. 모델의 추론 성능과 함께 자료 접근 권한, 작업 승인 절차, 비용과 결과 평가 기준을 확인하세요.

GPT-6.2 Sol·Astra 배포 점검​

Microsoft는 11월 20일부터 GPT-6.2 Sol과 GPT-6.2 Astra를 전 세계에 순차 배포한다고 발표했습니다. Copilot Studio에서는 두 모델 모두 eligible users 대상이지만, 모든 조직·지역의 즉시 GA를 뜻하지 않습니다. 제작자와 실행 사용자의 모델 선택 화면, 조직 자격, 라이선스와 Copilot Credits 조건을 확인하세요.

  • Microsoft 365 관리 센터에서 OpenAI 운영 모델의 하위처리자 접근 사용자·그룹을 확인합니다. Copilot Studio·Power Platform의 외부 LLM 설정도 별도로 적용됩니다.
  • OpenAI 운영 모델은 현재 정부·소버린 클라우드에서 사용할 수 없고, 해당되는 경우 국가 내 처리 약정에서 제외됩니다. Microsoft 운영 Azure OpenAI 모델은 하위처리자 설정과 별개이므로 실제 모델의 운영 주체와 데이터 조건을 구분합니다.
  • 프로덕션 에이전트를 바로 전환하지 말고 비운영 복사본에서 같은 지침·도구·지식·테스트 세트로 품질, 근거, 도구 호출, 확인 절차, 지연, 실패 복구와 소비량을 비교합니다. OpenAI의 API 가격·벤치마크를 Copilot Studio의 크레딧 요율이나 보장 성능으로 사용하지 않습니다.

Reliable Agentic Loops — November 2026 Guidance​

Microsoft's November guidance applies to agents powered by the Microsoft Copilot harness. It is design guidance rather than a new GA feature announcement. The central rule is to preserve flexibility inside explicit execution boundaries so the agent can recover from correctable errors without turning uncertainty into repeated model and tool calls.

Design boundaryProduction requirement
HandoffsDefine the input route, required format, returned state and observable success evidence for every tool, workflow and connected-agent handoff.
RetriesSeparate correctable invocation errors from terminal permission, configuration and structural failures. Set an attempt limit and verify that the prior attempt made no change before retrying a state-changing action.
Partial completionReturn created or changed state, the failed step, specific errors and whether a retry is safe. If the outcome is unknown, stop and escalate instead of repeating the whole task.
Runtime enforcementGive the agent only required tools and prefer read-only operations for retrieval. Enforce critical limits with validation, hooks or runtime controls where supported; instructions alone do not guarantee a stop.
Irreversible actionsRequire user confirmation or authorized human review before deletion, overwrite, external delivery or another irreversible action, including when recovery changes the route.
CompletionDefine observable output checks. A successful tool response is not proof that the user's requested result, delivery or link is complete.

Test both successful and failure paths before publishing. Include ambiguous tool results, missing dependencies, invalid source objects, mismatched file representations, permission denials and connected agents that already returned sufficient evidence. Review traces for repeated calls, route changes and work that continued after a stopping condition.

Microsoft's November 7 evaluation adds quantitative context. On the same tasks and models, the Microsoft Copilot harness made about twice as many model calls but used 15–21% fewer cost-weighted tokens because cache efficiency was 40 percentage points higher on average. Pass rate improved by 10.8 points on GPT-5.5 Chat and 22.1 points on Opus 4.8; after a failed tool call, production agents kept working 84–91% of the time, compared with under 7% for the Standard harness. Treat these as Microsoft benchmark and production observations, not a tenant-specific guarantee or SLA. Evaluate completion rate, cache efficiency, failure recovery and total token cost together rather than optimizing call count alone.

Model Change Assessment — November 2026 Preview​

Copilot Agent Kit's Model Assessment is a preview workflow for comparing an agent before and after a model change. It records a baseline, reruns the same tests, identifies regressions and persistent failures, and can compare up to three completed runs from the same test engine. Treat its AI recommendation and confidence as supporting evidence, not the release decision.

Test engineScope and requirement
Copilot Studio evaluationsSupported for Microsoft Copilot and Standard harness agents using the evaluation methods available to each harness. The active test-set name must contain MODELCHECK; publication isn't required.
Copilot Agent Kit testsStandard harness only. Requires a pipeline-enabled Agent Configuration and a Kit test set, and runs against the published agent.

Use a nonproduction copy. Selecting a model in Model Assessment changes the agent configuration, and Kit tests also publish the agent. Microsoft estimates about 150 Copilot Credits per assessment run; Kit tests don't report credits in Model Assessment, and AI summaries and recommendations can consume capacity even when a total isn't displayed.

Before comparing models, define pass rates, blocking failures, latency and reliability tolerance, safety and regional-processing approval, cost limits and accountable signoff. Keep instructions, tools, knowledge, identities and test data equivalent. Measure latency and consumption separately, preserve exported evidence, and retain the previously validated solution version because rollback is a redeployment rather than a configuration toggle.

Source: Assess model changes with Copilot Agent Kit (preview), updated November 17, 2026; Run and validate an AI model migration, updated November 17, 2026.

Copilot Studio 비용 관리 전환​

Microsoft 365 관리 센터에서 환경·에이전트용 지출 정책을 만들면 해당 범위의 기존 Power Platform 용량 할당과 연결된 청구 계획보다 우선 적용됩니다. 별도 이전 절차는 없으며, 정책 적용에 최대 12분이 걸릴 수 있습니다.

  • 처음에는 Specific environments로 범위를 제한하세요. All environments는 이후 추가되는 환경까지 포함합니다.
  • 앱·워크플로는 개별 선택 대신 환경 단위로 관리합니다. AI Builder를 사용하는 환경·에이전트·워크플로는 이 정책으로 옮기지 마세요. AI Builder 사용량은 지원하지 않습니다.
  • 리소스 정책이 사용자 정책보다 우선합니다. 같은 유형이 겹치면 해당 에이전트·사용자의 한도가 더 높은 정책이 적용되며, 한도를 합산하지 않습니다.
  • 환경을 정책에서 제외하거나 정책을 삭제하면 기존 Power Platform 설정이 다시 적용됩니다. 관리 역할은 자동으로 이전되지 않으므로 별도로 확인하세요.

제작자 추정값과 관리자 확정값을 연결하세요​

11월 24일 Microsoft 공식 지침은 비용 관리를 한 번의 예산 설정이 아니라 제작자의 설계 측정과 관리자의 정책 운영을 연결하는 반복 과정으로 설명합니다. 같은 대표 작업을 설계 변경 전후로 실행하고 완료율·품질·재시도와 함께 크레딧을 비교하세요.

  1. 제작자는 Preview·Evaluate에서 추정합니다. 이 값은 거의 실시간인 설계용 근사치입니다. 평가의 응답 생성 비용과 채점 비용을 분리하고, 실패·재시도까지 포함한 완료 작업당 크레딧으로 낮음·예상·높음 수요를 예측합니다.
  2. Monitor에서 확정 사용량을 대조합니다. 처리 지연이 있으므로 Preview·Evaluate 수치를 청구 원장처럼 사용하지 않습니다. 최종 처리된 Monitor 사용량으로 실제 절감 여부를 확인합니다.
  3. PPAC와 Microsoft 365 관리 센터의 범위를 구분합니다. PPAC는 환경 할당, 환경·에이전트·사용자 보고서와 에이전트별 한도를 관리합니다. Microsoft 365 관리 센터의 리소스 지출 정책은 선택한 에이전트·환경의 한도, 청구 방법, 경고를 통합하며 해당 범위에서 PPAC 설정보다 우선합니다.
  4. 역할과 대응 책임을 먼저 정합니다. Power Platform·Dynamics 365 관리자가 지출 정책을 만들려면 Microsoft 365 관리 센터의 AI Administrator 역할이 별도로 필요하고, 환경 관리자는 AI Reader로 사용량을 볼 수 있습니다. 한도 경고의 수신자·승인자·서비스 연속성 대응자를 정책과 함께 기록하세요.

리소스·환경 정책은 현재 공개 미리 보기이며, 사용자·그룹을 따르는 Copilot Studio용 identity 정책은 공식 발표에서 coming soon으로 안내됩니다. 실제 테넌트에 보이는 정책 유형과 서비스 범위를 확인한 뒤 단계적으로 적용하세요.

크레딧 관리 팁: 잔액이 있는데도 실행되지 않을 때​

크레딧 부족 알림만 보고 종량제를 켜기 전에 문제가 난 환경과 현재 적용되는 비용 정책부터 확인하세요. 구매한 총량과 그 환경에서 사용할 수 있는 양은 다릅니다.

먼저 확인할 다섯 가지​

  1. 환경을 맞춥니다. Studio에서 선택한 환경과 관리 센터에서 용량을 할당한 환경을 ID로 대조합니다. 개발·시험·운영 환경의 담당자와 비용 책임자도 기록하세요.
  2. 관리 위치를 확인합니다. Power Platform 관리 센터(PPAC)의 용량·에이전트 관리 화면에 Microsoft 365 리소스 지출 정책 적용 안내가 있는지 봅니다. 해당 정책이 적용 중이면 기존 PPAC 할당·청구 계획보다 우선합니다. PPAC 청구 계획 목록이 비어 있다는 사실만으로 과금 방식을 단정하지 마세요.
  3. 할당량과 사용량을 나눠 봅니다. PPAC에서 관리하는 환경은 Licensing > Copilot Studio의 선불 잔여량, 환경 할당량·소비량, 테넌트 미할당 용량 사용 설정을 확인합니다. 종량제 없이 선불 용량만 사용하는 구성도 가능합니다.
  4. 중단 조건을 찾습니다. 적용 중인 정책의 범위·한도·청구 방법과 에이전트 한도·중지 상태를 확인합니다. Microsoft 365 리소스 정책을 방금 연결했다면 적용에 최대 12분이 걸릴 수 있습니다. 사용자 정책만 만들고 환경에도 적용됐다고 가정하지 마세요.
  5. 작업 종류를 구분합니다. Microsoft Copilot harness는 제작·미리 보기·평가에서도 크레딧을 소비합니다. 미게시 에이전트도 비용이 생길 수 있습니다. 앱 제작, 에이전트 실행, agent flow 중 어디에서 실패했는지와 오류 시각을 기록하세요.

설정이 맞는데도 재현되면 환경·에이전트 ID, 오류 문구, 발생 시각, 적용 정책과 사용량 보고서를 모아 지원 요청을 준비하세요. 원인을 확인하기 전 추가 구매나 종량제 전환을 해결책으로 확정하지 않습니다.

출처: 용량·사용량 관리, Microsoft 365 비용 정책의 우선순위, Microsoft Copilot harness의 개발 단계 비용 관리.

알림과 실제 중단을 따로 설정하세요​

이강표 님의 「Copilot Studio Credit 사용 제한 설정 가이드」 4쪽은 환경 할당량과 초과 사용 설정을 함께 확인하도록 안내합니다.

“2·3번 모두 해제 시: 할당량만 사용, 소진 후 크레딧이 필요한 기능은 중단될 수 있음”

여기서 2번은 테넌트의 미할당 용량 사용, 3번은 종량제 청구 설정입니다. 같은 자료 5~6쪽은 에이전트별 월 한도와 사용량 중지·알림 설정을 설명합니다. 아래 절차는 이 구분을 바탕으로 최신 Microsoft 문서의 적용 범위와 제한을 보완했습니다.

PPAC에서 관리하는 개발 환경의 선불 사용량을 제한하려면 정해진 용량을 할당하고, Draw from the available capacity in my tenant를 끄며, 종량제 연결도 확인합니다. 같은 환경의 다른 에이전트·흐름·프롬프트에도 영향을 주므로 먼저 사용 목록을 확인하세요. 운영 환경은 중단 위험까지 고려해 예산과 추가 사용 승인 절차를 정합니다.

에이전트별로는 PPAC의 Manage Agents에서 월 한도와 알림, Hard stop을 확인하세요. Azure 예산 알림은 소비를 중단하지 않습니다. 에이전트 한도도 즉시 적용되지 않아 초과가 발생할 수 있고, 호출한 agent flow의 사용량은 별도로 검사됩니다. 새 에이전트에 조직의 기본 한도가 자동 적용되는 기능은 없으므로 정기 점검에 포함하세요.

사용량 급증은 환경 보고서에서 시작해 에이전트·기능·모델별로 좁혀 봅니다. 유료·비과금 크레딧을 구분하고 실제 Azure 청구 금액은 Azure Cost Management에서 확인하세요. PPAC 보고서는 대화별 토큰 원장을 제공하지 않으므로 모든 크레딧을 하나의 토큰 비율로 환산하면 안 됩니다.

Release Gate Model​

Gate 1Opportunity cardBusiness problem, user group, value hypothesis, knowledge sources, actions and risk level are documented.
Gate 2Design reviewInstructions, skills, memory, tools, identity, DLP, data boundary and cost assumptions are reviewed.
Gate 3Pilot validationResponse quality, permission boundary, action safety, evaluation results and support needs are tested.
Gate 4Production approvalOwner, monitoring, escalation, usage threshold, cost owner and retirement rule are confirmed.
Gate 5Operate and retireReview analytics, failure patterns, business value, cost and continued ownership on a regular cadence.

Customer Success Pattern​

Agent FactoryMulti-agent programCoordinator agent plus specialist agents for research, drafting, review and governance.AdoptionEnterprise AI adoptionConnect business scenarios, change management, champions, KPI and executive value reporting.Use CaseSales preparationMicrosoft 365 grounding with strict permission review and measurable preparation quality.SecuritySecurity intake workflowWorkflow agent with human review, audit trail, incident routing and escalation path.GovernanceAgent portfolio governanceAgent intake, prioritization, build standard, operating cadence and retirement rules.CoworkLong-running workApproval, ownership, quality, telemetry and cost control for longer-running AI work.

Common Mistakes​

OwnershipBuilding before ownership is clearRequire business owner, technical owner, reviewer and retirement rule before build.
AutomationTreating computer use as a shortcutClassify UI automation as high-governance automation with audit and recovery design.
PublishingAllowing unmanaged publishingUse environment strategy, DLP, release gates and approval before production exposure.
CostIgnoring cost forecastingEstimate usage and credits before pilot expansion, then monitor per agent.
DesignDesigning one large agentStart with the simplest suitable agent and tools. Add specialists only where distinct context, ownership or security boundaries justify the handoffs.
EvaluationSkipping test setsUse evaluation data, realistic conversations and regression checks before rollout.

사용자 정의 분석 지표와 MCP 연결​

사용자 정의 분석 지표는 미리 보기입니다. 원하는 업무 결과를 자연어로 설명하면 분류 또는 수치 점수 기준을 생성하고, 기본 분석 지표와 함께 결과를 계산합니다. 자동 생성한 기준이 실제 업무 성과를 제대로 나타내는지 예시 대화로 확인하세요.

MCP 연결 마법사는 Add a tool > New tool > Create new > Model Context Protocol에서 엽니다. 서버 설명은 에이전트가 호출 여부를 판단하는 데 쓰이므로 수행할 작업을 구체적으로 적고, 연결 인증과 도구 권한을 확인하세요. MCP 연결 절차를 참고하세요.
