Copilot Cowork Cost and Governance Guide

Copilot 모델·기능 안내

Claude Fable 5.2 · 단계적 배포의 앱별 제공 조건과 기능별 변경 내용을 확인할 수 있습니다. 공식 원문 확인: 2026-11-13.

Long-Running AI Work Governance

Move from chat to action only when ownership, approval and cost controls are ready

Copilot Cowork is designed for complex, long-running, multi-tool work. That makes it powerful, but it also means organizations need access control, budget guardrails, security review, value measurement and operating ownership before broad rollout.

Adoption PathPlatform UpdateRequest Governance Checklist
Cowork Control ModelControl first
01Use caseReserve Cowork for work that is multi-step, long-running or crosses tools.02CreditsPlan Copilot Credits, budgets, alerts, hard caps and reporting.03ApprovalsRequire human review for sensitive actions, external communication and file changes.04ValueCompare completed work, rework reduction, time saved, quality and credit consumption.
Cowork should not be the default for every promptKeep quick reasoning in Copilot Chat. Use Cowork when the task needs sustained execution, tool use, approvals, cost visibility and an accountable owner.

Executive Summary​

Microsoft 365 Copilot Cowork is not just another chat interface. It is an agentic work execution capability for complex, long-running, multi-tool tasks across Microsoft 365 context and business workflows.

Adoption planning should therefore start with operating controls, not feature excitement. Organizations need to prepare access scope, usage-based billing, Copilot Credits, spending limits, budget alerts, security governance, approval workflows and ownership before broad rollout.

Microsoft's June 30 update describes Copilot Cowork plugins as packages that can combine repeatable skills with secure connectors to business systems and be distributed through Microsoft Marketplace. Microsoft's June 16 GA announcement states that Cowork is generally available worldwide and requires a Microsoft 365 Copilot User Subscription License, with usage billed in Copilot Credits; individual plugin availability still varies, and capabilities marked as coming soon should not be treated as available. Before enabling a plugin, review its provider, requested data and actions, connector permissions, approval points for write or external actions, and the Microsoft 365 and Purview controls currently available for prompts, responses and generated artifacts. The June announcement listed DLP as coming soon. The current Purview support matrix now lists data loss prevention as supported for Cowork. Check the applicable policy conditions and test the intended content and action paths before rollout.

한국어 요약​

Copilot Cowork에 여러 단계의 업무를 맡기려면 사용할 도구와 자료, 작업 권한을 먼저 정해야 합니다.

사용 대상, 위임할 업무, 비용 승인자와 결과 검토자를 정하고, 시범 적용에서 사용량과 오류를 확인한 뒤 적용 범위를 넓힙니다.

장시간 걸리는 업무를 맡길 때는 완료 조건과 중간 승인 지점, 예산과 결과 검토자를 정하세요. 작업 기록을 확인하고 오류가 생겼을 때 중단·재시도할 담당자도 필요합니다.

Microsoft의 6월 16일 발표에 따르면 Copilot Cowork는 일반 공급(GA)되었으며 Microsoft 365 Copilot User Subscription License가 필요합니다. 사용량은 Copilot Credits로 청구됩니다. 6월 30일 발표된 플러그인은 반복해서 사용할 스킬과 업무 시스템 연결용 커넥터를 묶어 Microsoft Marketplace로 배포하는 방식입니다.

플러그인을 켜기 전에 제공자, 요청하는 자료와 권한, 실행할 작업을 확인하세요. 파일 변경이나 외부 시스템 작업에는 승인 절차를 정하고, 프롬프트·응답·생성 파일에 적용되는 Microsoft 365와 Purview 보호 기능을 확인합니다. 6월 발표에서는 DLP를 출시 예정으로 안내했지만, 현재 Purview 지원표에는 Cowork의 지원 기능으로 표시되어 있습니다. 적용할 정책과 자료 유형을 확인하고 실제 차단 동작을 시험하세요. 플러그인의 제공 여부는 해당 제공자의 현재 안내를 따릅니다. 관련 공식 발표는 아래 References에서 확인할 수 있습니다.

Claude Fable 5.2 모델 점검​

11월 11일 Microsoft는 Claude Fable 5.2를 Copilot Cowork와 Copilot Studio의 eligible users에게 순차 배포한다고 발표했습니다. 전면 GA나 모든 지역 제공으로 해석하지 말고 모델 선택 화면, 조직 자격과 관리자 설정을 함께 확인하세요.

  • Microsoft 365 관리 센터의 Anthropic 하위처리자 설정과 허용 사용자·그룹을 확인합니다. EU·EFTA·영국은 기본 꺼짐이며 정부·소버린 클라우드는 별도 제한이 있습니다.
  • Fable 계열은 조직 자격에 따라 Microsoft 하위처리자 조건 또는 Anthropic models with Data Retention 조건으로 제공될 수 있습니다. 후자는 별도 opt-in·Anthropic 약관이 적용되고 입력·출력 보존 조건이 다르므로 법무·보안 검토 없이 활성화하지 않습니다.
  • Copilot Studio는 Power Platform 관리 센터의 외부 LLM 설정도 확인합니다. 새 모델은 대표 업무의 정확도, 도구 호출, 지연, 비용과 실패 복구를 기존 모델과 비교한 뒤 적용합니다.

커넥터 카탈로그와 운영 점검​

11월 11일 공개된 10월 커넥터 업데이트는 Copilot 화면 간 공유 카탈로그, connector skills, 장기 실행 Tasks와 연결 관리 개선을 안내했습니다. 카탈로그 노출은 실제 커넥터 활성화, 공급자 권한이나 앱별 도구 지원을 자동으로 보장하지 않습니다.

  • source filter, Sources 메뉴, 누락 결과 제안과 inline reauthentication을 대표 사용자로 시험합니다. Chat·Word·Excel·PowerPoint·Researcher에서 실제 커넥터와 도구가 보이는지 각각 확인합니다.
  • 장기 실행 Tasks는 진행 상태와 최종 결과를 확인하고, 시간 제한·중복 실행·취소·부분 성공을 시험합니다. 공급자 계정·라이선스와 원본 권한은 별도로 필요합니다.
  • 연결 구성 편집, ACL 변경 뒤 ad hoc crawl, 오류 진단과 full crawl 진행률을 변경 기록에 남깁니다. 제한 사용자와 민감 자료로 Salesforce·ServiceNow·Confluence의 권한 일치와 과다 노출을 검증합니다.

에이전트 거버넌스 운영 모델​

Copilot Studio 에이전트의 통제는 한 포털에서 끝나지 않습니다. Power Platform은 환경·커넥터·공유 경계, Entra는 ID·접근, Purview는 지원되는 데이터 보호, Agent 365는 자산·도구·사용·비용 관찰, Defender는 위협 탐지와 대응을 담당합니다.

인벤토리에는 에이전트 소유자, agent identity·delegated user·agent user account 중 실제 ID 유형, 환경, 지식 원본, 도구, 대상 사용자, 데이터 분류, 비용 정책과 비상 중지 담당자를 기록하세요. agent registry나 map에 표시되는 정보·작업은 에이전트 유형, 게시 상태와 도구에 따라 다릅니다. 각 포털의 지원 범위를 확인하고 정책 적용 결과를 시험해야 합니다.

2026년 10월 배포 점검​

10월 30일 Microsoft 월간 업데이트는 Cowork와 연결된 기능의 제공 시점을 다음과 같이 구분했습니다. Cowork 자체의 GA와 개별 플러그인·Workspaces 기능의 배포 상태를 혼동하지 마세요.

  • 10월 배포: 역할별 플러그인, 작업 카탈로그, 이전 Copilot Chat·Cowork 작업 참조가 10월 배포로 안내됐습니다. 사용자에게 보이는 항목과 플러그인별 라이선스·연결 권한은 별도로 확인합니다.
  • 10월 Frontier → 11월 전 세계: OneNote·Planner 기능과 Audio Overview의 새 자료 형식·민감도 레이블 상속은 단계적 배포입니다. Frontier 결과를 전사 GA 근거로 사용하지 않습니다.
  • Workspaces: 기존 Notebooks가 협업형 Workspaces로 전환되며, Office 파일 직접 편집은 10월 Frontier 후 2027년 1월 전 세계 배포 예정입니다. JPG·PNG·CSV·TSV 참조 지원은 10월 배포 항목입니다.
  • Purview DLP: 월간 글은 Cowork DLP 확대를 10월 public preview로 안내하지만, 현재 DLP Learn 문서는 Cowork를 정책 적용 대상에 포함합니다. 지원되는 조건·작업과 최대 4시간의 정책 반영 시간을 확인하고, 민감도 레이블 파일·메일, 프롬프트의 민감정보 유형, 외부 웹 검색 차단을 각각 시험합니다.
  • 메모리 보존: 월간 글은 Copilot 메모리 보존 구성을 10월 배포로 소개하지만, 현재 Copilot 메모리 관리 문서는 메모리 전용 보존 규칙이 아직 없다고 설명합니다. 관리 화면과 최신 문서가 일치하기 전에는 메모리 보존을 운영 통제로 가정하지 말고, 일반 Copilot 상호작용 보존과 구분합니다.

로컬 Microsoft Edge 사용 점검​

11월 4일 릴리스 노트는 Cowork가 사용자 기기의 Microsoft Edge를 사용해 웹 기반 작업 단계를 수행하는 기능을 Current Channel 변경으로 안내했습니다. Cowork는 별도 Edge 탭에서 진행되며, 사용자는 대화에서 진행 상황을 보고 입력·승인하거나 직접 제어권을 가져올 수 있습니다.

  • 세션과 권한: 로그인된 로컬 Edge 세션을 사용하므로 해당 사용자가 접근할 수 있는 사이트와 자료 범위에서 동작합니다. Microsoft는 자격 증명, 쿠키와 세션 토큰이 기기에 남는다고 설명합니다. 이 설명이 대상 브라우저·기기 관리 구성에서 그대로 충족되는지 파일럿으로 확인하세요.
  • 기존 정책: ID, 조건부 액세스, 브라우저와 데이터 보호 정책을 우회하는 별도 권한이 아닙니다. 관리형 기기, 브라우저 프로필, 웹 사이트 세션과 다운로드·업로드 정책을 함께 시험합니다.
  • 승인 지점: 정보 조회와 초안 입력은 낮은 위험 시나리오부터 시작합니다. 외부 제출, 구매, 게시, 계정·권한 변경, 파일 업로드 같은 결과가 큰 작업은 실행 직전 승인을 요구하고 완료 결과를 검토합니다.
  • 배포 확인: 릴리스 노트의 Web 표기와 안전 배포 모델을 기준으로 대표 사용자의 Copilot Cowork와 Edge에서 기능 표시 여부를 확인합니다. Cowork 라이선스·지출 정책과 지역별 실제 제공 상태도 별도로 확인하세요.

Copilot 커넥터 쓰기 작업 통제​

11월 9일 Microsoft는 Copilot Chat과 Cowork에서 지원되는 federated connector의 생성·수정·삭제 작업을 GA로 발표했습니다. 연결 시스템의 사용자 권한으로 실행되며, 현재 Learn 문서는 사용자가 Microsoft 365 Copilot 라이선스를 보유하고 관리자 범위·커넥터 활성화·staged rollout에 포함되어야 한다고 안내합니다.

  • 기본 승인: 새 쓰기·수정·삭제 도구는 Needs approval로 시작합니다. 사용자는 매개변수를 검토하고 한 번, 현재 대화 동안 또는 이후에도 허용할 수 있습니다. 지속 허용은 커넥터 전체가 아닌 개별 도구에 적용됩니다.
  • 관리 한계: 쓰기 도구는 커넥터에 포함되며 읽기 도구와 별도로 관리자 활성화할 수 없습니다. 게시자 유형, 전체 사용자 범위, 개별 커넥터와 staged rollout으로 노출을 제한하고, 필요한 변경 작업을 제공하지 않는 커넥터를 선택하는 방식까지 검토하세요.
  • 데이터 경계: 승인 대기 중에는 쓰기 작업의 고객 데이터가 외부 서비스로 전송되지 않습니다. 승인 뒤에는 외부 서비스가 시스템 오브 레코드이며 사용자 권한으로 변경됩니다. 제공자 약관, 데이터 처리 위치와 Purview 감사 가능 범위를 확인하세요.
  • 파일럿 기준: 생성·수정·삭제를 각각 시험하고 취소, 부분 성공, 중복 실행과 완료 결과를 확인합니다. 삭제·외부 게시·계정 또는 금액 변경에는 Always allow를 사용하지 않고 조직의 별도 승인 절차를 유지하세요.

금융 데이터 커넥터 파일럿​

11월 10일 Microsoft는 Moody's·LSEG·FactSet 등 전문 금융 데이터를 Work IQ의 조직 맥락과 결합하는 Chat·Cowork·Excel 예시를 공개했습니다. 이는 측정된 생산성 결과나 모든 테넌트에 동일하게 제공되는 기능 목록이 아니라, 공급자별 계정과 커넥터 기능을 전제로 한 예시입니다.

  • 이중 권한 확인: Microsoft 365 Copilot 라이선스뿐 아니라 데이터 제공자 계정·구독 권한이 필요합니다. 커넥터 연결은 사용자의 원본 데이터 권한을 확대하지 않습니다.
  • 경험별 기능 확인: Chat·Cowork와 Excel에서 연결 경로와 지원 도구가 다를 수 있습니다. 대상 공급자, 앱, 읽기·쓰기 도구와 실제 사용자 표시 여부를 파일럿에서 확인합니다.
  • 근거 보존: 결과물에 공급자, 출처 날짜, 보고 기간, 통화·단위, 계산식과 누락값을 남겨 검토자가 원본으로 되짚을 수 있게 합니다.
  • 전문가 책임: 신용·투자·고객 조언의 가정과 결론은 담당자가 검토합니다. 공급자 약관, 조직의 기밀·보존·공유 정책과 관리자 staged rollout을 계속 적용합니다.

Plugin Catalog 준비와 패키지 검토​

Microsoft는 11월 17일 Ignite 개막에 맞춰 공개 Plugin Catalog를 시작할 예정이며, Copilot Home의 탐색 메뉴에도 플러그인이 표시되기 시작한다고 안내했습니다. 공개 카탈로그는 생태계 탐색용이므로 조직에서 즉시 사용할 수 있다는 의미로 해석하지 마세요.

  • 플러그인은 스킬, 도구(커넥터 포함), 에이전트를 함께 포함할 수 있습니다. 패키지 이름만 보지 말고 포함된 구성 요소와 각각의 권한을 검토합니다.
  • 탐색 메뉴 변경에도 기존 Microsoft 365 관리 센터 통제는 유지됩니다. 게시자 범주, 대상 사용자·그룹, 설치·차단, 사용자 요청 승인 상태를 확인합니다.
  • 공개 Catalog 노출, Microsoft 365 Store 제공, 조직 레지스트리 설치 가능 여부는 서로 다른 상태입니다. 11월 17일 이후 실제 테넌트와 한국 지역 제공 상태를 다시 확인합니다.
  • MCP 서버나 커넥터가 포함되면 쓰기·삭제·결제 도구를 별도로 식별하고, 지원되는 경우 도구별 차단과 최소 권한 동의를 적용합니다.

공식 근거는 Plugins at Microsoft Ignite 2026와 플러그인·스킬·MCP 서버 관리에서 확인할 수 있습니다. Ignite 세션 안내는 향후 기능을 포함할 수 있으므로 현재 제공 상태와 구분합니다.

Power Platform Admin Plugin Preview​

Microsoft announced the Power Platform Admin (preview) plugin for Cowork in October 2026. It provides read-only, AI-generated insights about Power Platform environments, apps, flows, agents, inventory, usage, ownership, capacity and licensing. It does not independently change administrative settings, so administrators should validate the source data before contacting makers or changing policies and environments.

  • A Microsoft 365 administrator can install the plugin for all users or selected users and groups from Agents > Tools > Registry. Installation does not grant Cowork access or Power Platform data permissions.
  • The account that connects through Power Platform for Admins V2 must have the Global Administrator, Power Platform Administrator or Dynamics 365 Administrator role. Confirm the intended account and tenant before completing OAuth consent.
  • Questions consume Copilot Credits. Pilot a small set of governance scenarios, measure actual consumption, and configure a Cowork spending policy before broad rollout.
  • Keep Ask Advisor approval scoped to trusted scenarios. Do not place passwords, access tokens or client secrets in a Cowork conversation, and review supported regions, AI subprocessors and Cowork compliance guidance for the target tenant.

Managed Environments are not required to ask questions. Their separate governance features retain their own requirements, and the preview plugin remains an insight layer rather than an administrative change engine.

Cost and Billing Control Plane​

Microsoft describes usage-based billing as actual usage measured in Copilot Credits. For Cowork planning, the cost discussion should focus on control, visibility and efficiency rather than price alone.

Cost ControlBudgeting must happen before adoption scales.Copilot Credits create flexibility, but long-running agentic work can consume variable resources. Teams should define budget owner, usage scope, reporting cadence and approval thresholds before expanding access.
AccessWho can use Cowork?Limit access by pilot group, role, business scenario and readiness level.BudgetHow much can be spent?Define tenant, group or user budget limits, hard caps and alert thresholds.RequestHow are more credits approved?Create a credit request process before users hit limits during active work.ReportingWho reviews consumption?Review usage by user, group, feature, task type and value signal.ValueWas it worth the credits?Compare cost with task completion, quality, time saved and rework reduction.ComplianceWhat needs retention?Review generated artifacts, prompts, responses, audit, eDiscovery and compliance needs.

Spending policy scope​

The Auto-apply new services option is enabled by default for spending policies. Newly supported Copilot services and agents can therefore inherit an existing policy. Turn this option off for policies that require a separate review before adding a service, and check the actual service list, users and limits. Cowork access requires a spending policy that includes Cowork; installing a plugin or changing its registry entry does not grant that access. Even a one-credit limit grants access until that limit is reached. To block access, exclude the user from every policy that selects Cowork. Disabling Anthropic models alone also leaves access through other allowed models. See Cowork access controls.

The Microsoft 365 admin center manages supported services such as Cowork and Work IQ API. Copilot Studio environments and agents can now opt in to resource-based spending policies in this dashboard. Power Platform controls remain in effect for scopes that have not opted in; not every Copilot experience uses this dashboard. The Copilot Cost Management API reports credits rather than currency charges or invoices. See current billing scope and policy behavior.

Recommended Adoption Pattern​

Start small, measure carefully, then expand. A strong first phase is not a full enterprise rollout. It is a controlled pilot with clear cost boundaries, selected users and measurable scenarios.

The pilot should answer three questions:

  1. Which workflows create meaningful business value?
  2. How much credit consumption does each workflow pattern create?
  3. What governance controls are required before scale-out?

Once these answers are available, the organization can move from technical enablement to a sustainable operating model.
