What To Include​

When requesting a discussion or document, include only safe business context at first.

01WorkloadMicrosoft 365, Security, Copilot, AI Agent, Azure, Migration or Proposal.
02PurposePresales, architecture workshop, assessment, proposal, implementation planning or handover.
03IndustryRetail, manufacturing, finance, logistics, healthcare, construction or enterprise group.
04Expected OutputChecklist, SOW, WBS, architecture note, governance model, workshop deck or executive summary.

Confidentiality Boundary​

Customer names, tenant identifiers, project code names, commercial terms, internal filenames and customer-specific architecture details should not be included in the first public request.

Level 1Public PatternSafe for public website and search engines: anonymized architecture pattern or generic decision framework.
Level 2Sanitized SampleSafe after contact: edited SOW, WBS or checklist structure with sensitive details removed.
Level 3Context ReviewRequires confirmed business context: editable template, workshop deck or assessment workbook.
Level 4Customer-SpecificNot shared publicly: tenant-specific diagrams, exports, security exceptions or commercial details.

Do Not Include In The First Request​

  • customer legal name
  • tenant ID, domain list or user export
  • contract value, discount or price assumption
  • internal project code name
  • security exception details
  • architecture diagrams with real IP ranges or system names

Use industry, workload, project phase and desired output type instead.
