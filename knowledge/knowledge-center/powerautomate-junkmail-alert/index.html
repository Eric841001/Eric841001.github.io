Power Automate 정크 메일 알림

EXCHANGE ONLINE ALERT AUTOMATION

Turn hidden Junk Email activity into visible security signals

This pattern uses Power Automate to collect junk mail indicators and notify Teams or email channels before missed messages become operational risk.

EXOMailbox
FlowTrigger
TeamsAlert
OpsReview

Executive Summary​

This guide describes how Power Automate can monitor Exchange Online Junk Email folders and generate automated notifications.

The objective is to improve visibility of potentially malicious email activity and reduce missed security events.

Business Scenario​

Use this pattern when users need a reminder to review selected Junk Email folders.

Important emails may be incorrectly classified.

Organizations require:

  • Junk email visibility
  • Alert notification
  • Security monitoring
  • User awareness
  • Reporting

Solution Architecture​

Junk mail alert architectureExchange signal to team notification
01Exchange OnlineMonitor selected Junk Email folders or mailbox signals for messages requiring visibility.
02Power AutomateTrigger workflow, collect message metadata and apply filtering logic.
03Teams notificationNotify a security, help desk or operations channel with actionable context.
04Email summarySend summary or evidence record for follow-up, tuning and reporting.

Workflow Overview​

Alert workflowDetect, enrich, notify
01New junk emailA message lands in scope for monitoring based on mailbox or folder criteria.
02Collect metadataCapture sender, subject, received time and recipient; add security classification only through a separate data source.
03Generate alertFormat relevant context for review without exposing unnecessary sensitive content.
04Notify and reportPost to Teams, send email summary and maintain visibility for tuning.

Trigger Design​

Exchange Online Trigger​

Use the Office 365 Outlook connector's When a new email arrives (V3) trigger, selecting the intended mailbox's Junk Email folder. Validate the connection account and use the appropriate shared-mailbox trigger when relevant. The connector reference documents permissions, limits and trigger behavior.

This is a notification pattern, not a guaranteed security-event pipeline. The V3 trigger skips messages above the smaller of the Exchange administrator's size limit and 50 MB; protected messages or invalid message content may also be skipped. Trigger delivery can occasionally be delayed by up to one hour. A message moved between folders may not trigger as expected; test direct arrival, later moves, duplicates, protected messages and throttling. Quarantined mail is separate from a mailbox's Junk Email folder. Correlation with Defender/Sentinel/Purview is an additional design requiring its own data access and implementation. Do not copy message bodies or sensitive attachments into broad notification channels.

Connection and attachment settings​

For a shared mailbox, use When a new email arrives in a shared mailbox (V2) and verify the connection account's mailbox access. For user-to-user mailbox sharing, the connector requires full mailbox access; permission to send mail alone is insufficient.

For a metadata-only alert, set Include Attachments to No. Downloading every attachment in the trigger can cause a timeout when many messages arrive together. If a separate approved process needs an attachment, retrieve it with Get Attachment (V2) after filtering the message. The connector also limits each connection to 300 API calls per 60 seconds; mailbox-side Exchange limits apply separately. These are connector limits, not a guarantee that every message will produce an alert. See Outlook connector limits and attachment handling.

시험 메일은 도착했는데 알림이 없을 때​

  1. 먼저 실행 기록을 확인합니다. 흐름을 저장하고 테스트를 시작한 뒤 지정한 사서함의 정크 메일 폴더로 새 시험 메일이 직접 배달되도록 합니다. 기존 메일을 다른 폴더에서 옮기는 시험은 따로 진행하세요.
  2. 실행 기록이 없으면 흐름이 켜져 있는지, 연결 계정과 폴더가 맞는지, 시험 메일이 트리거 조건에 맞는지 확인합니다.
  3. 실행 기록이 있으면 해당 실행을 열고 Teams나 메일 발송 단계의 상태를 확인합니다. 실패한 단계의 입력과 오류 메시지를 보고 연결이나 수신 대상을 수정한 뒤 새 시험 메일로 다시 확인하세요.

알림에 첨부파일 내용이 필요 없다면 Include Attachments를 No로 둡니다. 이 설정에서도 첨부파일 이름과 ID 같은 정보는 트리거 결과에 남습니다. 알림에 표시할 필드는 따로 선택하세요. 흐름 실행 오류 확인 · Outlook 커넥터의 첨부파일 처리

한국어 요약​

Exchange Online의 정크 메일 폴더를 확인하고 Teams나 메일로 알리는 Power Automate 구성 예시입니다.

보안팀과 서비스데스크가 확인할 조건을 정해 불필요한 알림을 줄입니다. 발신자, 수신자, 제목과 수신 시각 등 필요한 항목만 알림에 담으세요.

Operational Checklist​

CheckpointValidation Question
감시 범위어떤 사용자 또는 공유 사서함의 정크 메일 폴더를 감시할 것인가?
알림 조건모든 메일을 알릴 것인가, 특정 조건만 알릴 것인가?
RecipientTeams 채널, 서비스데스크 사서함과 SOC 작업 목록 중 어디로 보낼 것인가?
불필요한 알림 줄이기일별 요약, 고위험 메일만 알림, 지정 사용자만 알림 같은 제한 조건이 필요한가?
Evidence발신자, 제목, 수신 시각, 수신자, URL, 첨부파일 정보를 남기는가?
Ownership흐름 담당자, 대체 담당자와 실패 알림 수신자가 정의되어 있는가?
