Defender for Endpoint Linux 온보딩

MDE LINUX ONBOARDING

Extend Defender visibility to Linux servers and workloads

Linux onboarding should validate distribution support, connectivity, package deployment, sensor health and Defender portal visibility before operational handover.

LinuxServer
AgentMDE
PortalSignal
OpsOwner

Executive Summary​

This guide describes Linux onboarding procedures for Microsoft Defender for Endpoint.

Linux onboarding enables endpoint visibility, threat detection and vulnerability management for Linux servers and workloads.

Supported Distributions​

Support depends on the distribution, exact version, architecture and Defender build, not the distribution name alone. Use the current Linux requirements matrix and release notes. Record /etc/os-release, kernel/architecture and installed mdatp version in deployment evidence. Do not infer support for an end-of-life CentOS or other release from a generic “Yes” row.

10~11월 지원 변경과 업데이트​

  • Amazon Linux 2 ARM64: Defender의 공식 지원 종료일은 2026년 10월 31일입니다. 해당 서버의 이전 완료 여부를 확인하고, 남은 서버는 지원되는 배포판으로 전환하세요. 이 공지를 Amazon Linux 2의 모든 아키텍처가 같은 날 종료된다는 뜻으로 해석하지 마세요.

  • Linux 데스크톱: 지원 범위가 Public Preview로 확대됐습니다. 서버 지원 배포판을 기준으로 배포판·커널·아키텍처 조건을 확인하세요. 데스크톱에는 Defender for Endpoint P2 권한이 필요하고, 서버에는 Defender for Servers 등의 서버용 라이선스가 필요합니다. Microsoft 365 E5·E7의 사용자 권한만으로 서버 라이선스를 충족한다고 판단하지 마세요.

  • 11월 Linux 빌드: 101.26101.0000은 OpenSSL을 3.6.4로 올리고, Defender 포털에 CentOS의 세부 버전이 빠지던 문제와 패키지 검사 중 메모리 사용을 개선했습니다. 최신 릴리스 기록과 배포 저장소의 버전을 대조하세요.

  • 10월 Linux 빌드: 101.26091.0004는 Azure Linux 4 지원과 TCP 소켓 바인딩 이벤트를 추가합니다. 이벤트 수집은 한 달에 걸쳐 순차 적용되며, 활성화된 기기에서는 Advanced Hunting의 DeviceNetworkEvents에서 ActionType이 ListeningConnectionCreated인 기록을 확인할 수 있습니다. 업데이트 직후 모든 기기에 기록이 나타난다고 가정하지 마세요.

출처: Linux 지원 배포판·라이선스·지원 종료 공지, 10월 Linux 릴리스. 배포 전 저장소의 제공 버전과 실제 기기의 mdatp health 결과를 대조하세요.

Linux 백신 감사 모드​

Linux의 백신 감사 모드가 정식 제공됩니다. 버전 101.26062.0007 이상에서 실시간 탐지와 알림을 수행하지만 파일을 자동 격리하거나 프로세스를 종료하지 않습니다. 운영 영향 평가에 사용할 수 있으나 차단 모드와 같은 보호 효과로 해석하면 안 됩니다.

현재 모드는 다음 조회 명령으로 확인합니다.

mdatp health --field antivirus_enforcement_level

audit는 실시간 탐지를 수행하며, 실시간 탐지를 하지 않는 passive와 다릅니다. 실제 적용 전 탐지 결과와 운영 영향을 검토하세요.

근거: Defender 10월 변경, Linux 백신 모드와 조회 명령.

Prerequisites​

Required:

  • Python for the Python-based onboarding script; follow the chosen deployment method's requirements
  • Internet Connectivity
  • Root Access
  • Supported Linux Version

Before onboarding, confirm whether the server is internet-connected, proxy-routed or isolated. Before installation, check package repository access, TLS inspection exceptions and outbound firewall rules. Defender for Endpoint on Linux supports static or transparent proxies; PAC, WPAD and authenticated proxies are not supported. Treat these checks as part of the deployment readiness review, not as post-install troubleshooting.

Installation Workflow​

This section describes manual installation. Microsoft now recommends the Defender deployment tool; choose the method that fits your deployment process.

Use the official distribution-specific installation procedure. Repository configuration and package signing-key registration differ across Debian/Ubuntu, RHEL-family and SUSE; one generic command sequence is not portable.

Before installing:

  1. Read cat /etc/os-release and uname -m, then match the exact supported distribution/version.
  2. Configure the official production repository for that distribution and version using the linked procedure.
  3. Register Microsoft's package-signing key in the format and keyring location prescribed for that package manager. Downloading or printing the key alone does not register trust.
  4. Refresh repository metadata, install mdatp with the matching package manager, and record the selected package version.
  5. Apply the tenant-specific onboarding package, then validate health and cloud connectivity.

The following commands are read-only preflight checks, not a standalone installer:

cat /etc/os-release
uname -m
command -v python3

For Debian/Ubuntu the final package-install command is sudo apt-get install mdatp, after repository/key configuration and metadata refresh. RHEL/SUSE use their respective package-manager instructions. Follow the official repository instructions instead of inventing a download URL or reusing a different distribution's configuration.

패키지 설치·업그레이드 전 확인​

101.26091.0003부터 Linux 패키지에 iptables가 필요하며, RPM 패키지에는 libacl도 필요합니다. 설치 스크립트와 Defender 배포 도구는 이 의존성을 자동 설치합니다. rpm이나 dpkg로 직접 설치할 때는 의존 패키지를 먼저 설치해야 합니다. 누락되면 설치나 업그레이드가 실패할 수 있습니다.

배포판의 주요 버전을 업그레이드하거나 Defender 업데이트 채널을 바꿀 때는 기존 Defender를 제거한 뒤 다시 설치하는 절차도 준비하세요.

근거: 11월 12일 패키지 의존성 공지, 수동 설치의 OS·채널 변경 조건.

Onboarding​

Download the Linux Server / Local Script onboarding package from the intended tenant’s Defender portal, extract it and copy the script to the target device. The following example uses Python 3; follow the distribution-specific interpreter requirement rather than assuming every supported older distribution provides the same interpreter.

sudo python3 MicrosoftDefenderATPOnboardingLinuxServer.py

Validation​

Check status.

mdatp health

Test service connectivity separately from the health summary.

mdatp connectivity test

The health summary and a nonempty organization ID alone do not prove every service endpoint is reachable. See the Linux connectivity test and command reference.

Check Org ID.

mdatp health --field org_id

Enable real-time protection only after checking compatibility with existing security software. Microsoft’s Linux prerequisites do not support active Defender alongside another Fanotify-based blocking security solution; use the documented passive-mode coexistence configuration where applicable. The documented exception is FAPolicyD on RHEL/Fedora when mdatp health reports a healthy state. Confirm the intended centrally managed policy before running this local configuration command.

sudo mdatp config real-time-protection --value enabled

Linux 에이전트 버전은 출시 후 9개월이 지나면 만료됩니다. 만료 뒤에도 보안 인텔리전스 업데이트는 제공되지만, 제품 수정 사항과 개선 사항을 받으려면 에이전트도 업데이트해야 합니다. OS 지원 종료일과 설치된 에이전트의 만료일을 같은 날짜로 간주하지 마세요. Linux 릴리스 정책에 따라 기기에서 만료일을 조회합니다.

mdatp health --field product_expiration

Operational Acceptance Criteria​

Use the following criteria before marking the onboarding as complete:

  • the device appears in Microsoft Defender XDR with the expected hostname and operating system
  • mdatp health reports the expected protection and organization state, and mdatp connectivity test verifies the required service connectivity
  • vulnerability management data is visible for the onboarded server
  • alert routing to the SOC or operations team has been validated
  • proxy and update paths are documented for future patching or incident response

For production Linux servers, capture a validation screenshot or command output as handover evidence. Record the installation, onboarding, protection and connectivity results separately so the handover states what was actually tested.

Security Best Practices​

  • Enable RTP after validating coexistence; preserve the documented passive configuration when another security solution requires it
  • Enable Vulnerability Management
  • Monitor Health Status
  • Integrate with SIEM
  • Enable Alerting

한국어 요약​

Linux 서버에 Defender for Endpoint를 설치하고 조직에 등록하는 절차입니다.

배포판과 버전, 패키지 저장소, 네트워크와 라이선스 조건을 확인한 뒤 설치합니다. 완료 후에는 기기의 보호 상태와 포털 등록 결과를 함께 확인하세요.
