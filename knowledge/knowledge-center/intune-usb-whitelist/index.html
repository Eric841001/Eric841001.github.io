Intune USB 장치 허용 목록 제어

Executive Summary​

Organizations often need to block unauthorized USB storage devices while allowing approved corporate USB devices.

Microsoft Intune and Microsoft Defender Device Control can implement granular USB access policies.

Review audit evidence, the approved device inventory and exception procedures before enforcement. Use the pilot results to identify workflows that the proposed restrictions would interrupt.

한국어 요약​

승인된 USB 저장장치의 접근을 허용하고 나머지 이동식 저장장치를 제한하는 방법을 설명합니다.

Defender Device Control과 Intune으로 사용 기록을 수집한 뒤 허용 목록과 예외 처리 절차를 정합니다. 업무에 미치는 영향을 확인한 다음 차단 정책을 적용하세요.

Business Scenario​

Typical requirements:

  • Block personal USB storage
  • Allow encrypted corporate USB drives
  • Restrict file copy operations
  • Maintain audit trail
  • Meet compliance requirements

Architecture​

USB device control pathApproved media only
01Endpoint userUser connects removable media to a managed Windows device.
02Intune policyDevice Control settings are assigned through scoped groups and rollout rings.
03Defender controlDefender evaluates approved device identifiers, read/write rules and audit behavior.
04Allow or blockApproved USB devices continue; unauthorized devices are blocked or audited.

Supported Controls​

This guide covers supported removable-media access controls, not disabling every USB bus device such as keyboards or cameras. Match the Device Control policy type, Windows version, Defender build, onboarding and license prerequisites to the current Intune deployment procedure. Intune is a separate entitlement; the Device Control profile is not supported for Windows Server devices managed through Defender security settings management.

Encrypted and composite USB devices​

An approved serial number identifies a device; it does not establish that the drive is encrypted. For the encrypted-media requirement, distinguish Windows BitLocker write restrictions from Defender Device Control rules that match BitLocker encryption state, which Microsoft currently labels Preview.

A physical USB device can expose both removable-media and Windows Portable Device entries. Include every required entry when testing an approved device; allowing only one interface can leave other operations blocked. See USB access and BitLocker controls.

Audit rules and default enforcement​

An audit rule records activity; it does not itself allow or deny access. When only audit rules are configured, access follows the default enforcement setting. Intune does not preserve the order shown in the policy list, so explicitly exclude approved devices from overlapping Deny rules instead of relying on an Allow rule appearing first. The Intune graphical interface does not change the default enforcement setting. Confirm the effective default and test both approved and unapproved media before rollout. See Device Control rule behavior.

Implementation Approach​

Rollout modelAudit before enforcement
01Audit activityCollect USB usage evidence before blocking business workflows.
02Build inventoryDocument approved devices, owners, serials, encryption and exception rules.
03Pilot rulesTest allow, block and read-only behavior with support and rollback paths.
04Operate exceptionsMonitor bypass attempts, approve exceptions and refine the allow list.

Validation​

  • Approved USB accessible
  • Unapproved USB blocked
  • Audit logs generated
  • User notification verified

Deliverables​

  • USB Control Policy
  • Approved Device Inventory
  • Test Report
  • Operational Runbook

Decision Checklist​

DecisionRecommended Question
Approved deviceWhich USB devices are business-approved and how are they identified?
EnforcementWhich user groups move from audit to block first?
ExceptionWho approves temporary or project-based USB use?
MonitoringWhich logs prove block, allow and read-only behavior?
User impactHow are users notified when a USB device is blocked?

Common Risks​

  • Building an allow list without serial number validation
  • Enforcing block policies before audit data is reviewed
  • Not planning exceptions for manufacturing, field or executive users
  • Failing to monitor policy bypass attempts
