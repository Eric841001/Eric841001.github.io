M365 Apps 로컬 저장소 제한 및 클라우드 저장 강제

Microsoft 365 Apps의 Word·Excel·PowerPoint에서 새 파일 저장과 다른 이름으로 저장에 사용할 로컬·네트워크 위치를 제한합니다. OneDrive·SharePoint 같은 클라우드 위치만 제공하도록 구성하는 정책입니다. 배포 방법은 Active Directory 그룹 정책과 Microsoft 365 Apps 관리 센터의 Cloud Policy 두 가지입니다.

적용 조건​

Cloud Policy 공식 문서는 사용자 기반 정책 배포와 GPO 대비 우선순위를 설명합니다. 배포 전 대상 Office 빌드의 ADMX 또는 Cloud Policy 카탈로그에서 아래 정책과 레지스트리 값의 지원 여부를 확인하세요. GPO와 Cloud Policy의 일반적인 우선순위만으로 개별 설정의 지원 여부를 판단할 수는 없습니다.

  • Windows용 Microsoft 365 Apps for enterprise 구독. Cloud Policy에서 Apps for business는 개인정보 보호 관련 정책만 지원하며, Office LTSC 같은 볼륨 라이선스 제품에는 적용되지 않습니다.
  • 최신 Office ADMX/ADML 템플릿을 사용하는 Active Directory 환경 또는 Microsoft 365 Apps 관리 센터
  • Windows와 Office의 실제 버전을 기록하고 시험용 사용자에게 먼저 적용합니다. 저장 화면과 기존 파일 편집·저장 동작을 각각 확인하세요.

동일한 정책이 AD GPO와 Cloud Policy에 모두 구성되면 Cloud Policy가 우선 적용됩니다.

방법 1: Active Directory 그룹 정책​

Microsoft 공식 ADMX/ADML의 Office 정책 템플릿을 중앙 저장소의 PolicyDefinitions에 반영합니다. 사용자 구성의 Microsoft Office 2016 → Miscellaneous에서 Restrict saving on non-Cloud locations 정책(L_CloudOnlySaving)을 사용으로 설정하세요. 표시 이름은 ADML 언어에 따라 달라집니다.

클라이언트에 정책이 적용되면 다음 레지스트리 값을 확인할 수 있습니다.

HKEY_CURRENT_USER\Software\Policies\Microsoft\Office\16.0\Common\FileIO
  enablecloudonlysaveasmode = 1 (DWORD)

필요하면 정책을 갱신한 뒤 Office 앱을 다시 시작합니다.

gpupdate /force

Word, Excel 또는 PowerPoint에서 다른 이름으로 저장을 열었을 때 로컬 디스크가 제외되고 클라우드 저장소만 표시되는지 확인합니다.

방법 2: Microsoft 365 Apps 관리 센터​

  1. Microsoft 365 Apps 관리 센터에 접속합니다.
  2. 사용자 지정 > 정책 관리 > 만들기로 이동합니다.
  3. 시험용 사용자가 포함된 Microsoft Entra 그룹을 먼저 할당합니다. 정책은 사용자 개체에 적용되며, 그룹 안의 장치 개체는 무시됩니다.
  4. 정책 구성에서 Restrict saving on non-Cloud locations를 검색합니다. 사용하는 카탈로그에서 제공되지 않으면 배포됐다고 판단하지 말고 GPO 지원 여부를 따로 확인하세요.
  5. 설정을 사용으로 구성하고 배포합니다.

Cloud Policy를 수신한 클라이언트에서는 다음 위치를 확인합니다.

HKEY_CURRENT_USER\Software\Policies\Microsoft\Cloud\Office\16.0\Common\FileIO
  enablecloudonlysaveasmode = 1 (DWORD)

Cloud Policy와 AD GPO가 충돌하면 Cloud Policy가 우선합니다. Windows에서는 Office에 로그인한 기본 계정의 정책이 적용되므로, 여러 계정으로 로그인했다면 어떤 계정이 기본인지 확인하세요. 계정을 바꾼 뒤에는 Office 앱을 다시 시작하고 정책 수신과 저장 화면을 확인합니다. GPO 적용 여부는 AD 사용자 정책 대상과 실제 적용 결과로 따로 확인하세요.

정책 배포가 즉시 끝나는 것은 아닙니다. Cloud Policy를 수신한 대상 사용자의 기본 확인 간격은 90분이며, 정책이 적용되는 시점에는 Office 앱 재시작도 필요합니다. 관리 센터의 설정 저장과 클라이언트의 적용 완료를 구분하세요.

검증 체크리스트​

  • 정책 대상 사용자 또는 그룹이 정확한지 확인
  • 정책 레지스트리 enablecloudonlysaveasmode=1 확인
  • Office 앱 재시작 후 Save As 화면 확인
  • 로컬 디스크·바탕 화면·문서 폴더·네트워크 공유가 새 파일의 저장 대상으로 제공되지 않는지 확인
  • OneDrive 및 SharePoint 위치가 정상적으로 표시되는지 확인
  • 오프라인, 동기화 장애, 클라우드 로그인 만료 시 사용자 경험 확인
  • Cloud Policy와 GPO를 함께 사용할 경우 우선순위 확인

통제 범위와 한계​

이 설정은 Microsoft 365 Apps의 저장 UI를 클라우드 중심으로 제한하는 정책입니다. 운영체제 전체의 파일 쓰기, 다른 애플리케이션의 저장, 복사·붙여넣기, 스크린샷 또는 이미 존재하는 로컬 파일까지 모두 차단하는 통제는 아닙니다. 더 강한 통제가 필요하면 Endpoint DLP, AppLocker/WDAC, 디바이스 규정 준수 및 조건부 액세스를 함께 설계해야 합니다.
