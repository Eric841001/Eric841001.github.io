Exchange Online Message Search and Purge

EXCHANGE ONLINE INCIDENT OPERATION

Search, validate and purge risky mail with approval evidence

Message purge should be treated as a controlled incident response procedure because it can permanently remove content from user mailboxes.

FindQuery
CheckResult
ApproveOwner
PurgeReport

Executive Summary​

This guide describes how to search and purge incorrectly sent or risky email messages from Exchange Online mailboxes using Microsoft Purview compliance search and PowerShell.

This procedure should be treated as a controlled incident response operation because it can permanently delete messages from user mailboxes.

Business Scenario​

Organizations may need to remove messages when:

  • A confidential email was sent to the wrong recipients
  • A malicious message was delivered to multiple users
  • A phishing campaign bypassed initial controls
  • An internal mail was sent with incorrect attachment or content
  • Legal or compliance team requests controlled removal

Important Warning​

Message purge is a destructive operation.

Before execution:

  • Obtain approval from authorized owner
  • Confirm legal and compliance position
  • Validate search query carefully
  • Use a pilot search before purge
  • Document all actions

Process Overview​

Message purge control flowValidate before destructive action
01Incident reportedConfirm business owner, risk type, sender, recipients and message identifiers.
02Compliance searchDefine query, create search and validate matched items before purge.
03Approval gateObtain authorized approval because purge can permanently remove mailbox content.
04Purge and reportExecute controlled purge and document result, scope, timestamp and evidence.

Required Permissions​

A search permission does not itself grant permission to delete. Confirm the Compliance Search / eDiscovery search permissions and the separate Search And Purge role in Microsoft Purview. Exchange Administrator alone is not a substitute for the purge role. Role-group names and assigned permissions must be checked in the actual tenant.

Current connection requirements​

For interactive eDiscovery PowerShell, use ExchangeOnlineManagement 3.9.0 or later and a search-only session:

Import-Module ExchangeOnlineManagement
Connect-IPPSSession -UserPrincipalName '<authorized-admin-UPN>' -EnableSearchOnlySession

This example connects; it does not run a search or purge. App-only authentication for eDiscovery cmdlets in Security & Compliance PowerShell is unsupported. Existing certificate-based examples do not change that status. Use supported Microsoft Graph APIs for unattended automation where available, and check which operations the API covers. See eDiscovery app-only support status. See current connection requirements.

Choose the supported purge method​

Case and methodCurrent documented limit and boundary
Non-premium eDiscovery / PowerShellUp to 10 items per mailbox/location in a purge action; intended for incident response, not bulk mailbox cleanup
Premium-enabled case / Microsoft GraphUp to 100 items per location; verify case creation method and supported item types in the official procedure
Mixed methodsDo not combine PowerShell and Graph purge methods for the same process; follow the method supported by the case

Find and delete email in eDiscovery explains the case and method restrictions. A single completed action does not prove every matching item was removed. Review counts, scope, action results, unindexed items and remaining matches. Holds, retention and Recoverable Items affect final removal; HardDelete is not a promise of immediate physical erasure.

Step 1. Define Search Criteria​

Search criteria may include:

CriteriaExample
SubjectSpecific mail subject
SenderSender email address
DateSent date
Recipient ScopeAll mailboxes or selected mailboxes
KeywordsUnique message content

Step 2. Create Compliance Search​

Example structure:

New-ComplianceSearch `
  -Name "Search-Message-Removal" `
  -ExchangeLocation All `
  -ContentMatchQuery 'subject:"<subject>" AND sender:"<sender>" AND sent:"<date>"'

Adjust the query to match the actual incident.

Step 3. Start Search​

Start-ComplianceSearch -Identity "Search-Message-Removal"

Check status:

Get-ComplianceSearch -Identity "Search-Message-Removal"

Proceed only after the search status is completed and results are validated.

Step 4. Purge Message​

Hard delete example:

New-ComplianceSearchAction `
  -SearchName "Search-Message-Removal" `
  -Purge `
  -PurgeType HardDelete

Use HardDelete only when approved.

Validation​

Validate that:

  • Review action status, item counts and remaining matches; do not infer complete removal from action completion alone
  • Validate the expected mailbox visibility and Recoverable Items / hold / retention behavior
  • Recoverable Items behavior is understood
  • Search action completed successfully
  • Incident record is updated

Operational Controls​

한국어 요약​

Exchange Online에서 잘못 발송했거나 보안 사고와 관련된 메일을 검색하고 삭제할 때 확인할 절차입니다. 메시지 회수와 관리자 삭제는 서로 다른 작업입니다.

검색 조건과 대상, 승인 기록, 보존 정책과 법적 보류 여부를 확인하세요. 실제 삭제 전에 다른 담당자가 검색 결과를 검토하고 시험해야 합니다.
