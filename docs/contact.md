## 요청할 수 있는 자료 {/* #what-can-be-requested */}

편집 가능한 양식과 고객 보고용 자료는 공개 사이트에 올리지 않습니다. 목적과 공유 범위를 확인한 뒤 브리핑과 함께 안내합니다.

| 자료 | 내용 |
| --- | --- |
| Microsoft 365 진단표 | 현황 검토, 영역별 진단 결과, 성숙도 점수와 로드맵 |
| 작업 범위 기술서(SOW) 양식 | 범위, 산출물, 전제 조건, 제외 사항과 검수 기준 |
| 작업 분류 체계(WBS) 양식 | 작업 구조, 선후 관계, 마일스톤과 책임자 |
| 위험 관리 대장 양식 | 프로젝트·보안·도입·전환·운영 위험 구조 |
| 에이전트 운영 모델 | 접수, 우선순위, 구축 방식, 승인, 사용 기록과 폐기 |
| 고객 성공 참조 패턴 | 업종·상황별로 익명화한 진행 방식 |

## 공유 범위와 보안 기준 {/* #confidentiality-boundary */}

고객사 이름, 테넌트 식별자, 프로젝트 코드명, 계약 조건, 내부 파일명과 고객 고유의 설계 정보는 첫 연락에 넣지 마세요.

| 단계 | 공유 범위 |
| --- | --- |
| 1. 공개 패턴 | 공개 사이트와 검색엔진에 올려도 되는 익명화한 설계 패턴과 판단 기준 |
| 2. 정리한 예시 | 연락 후 공유: 민감 정보를 뺀 SOW·WBS·점검표 구조 |
| 3. 맥락 검토 | 업무 맥락 확인 후 공유: 편집 가능한 양식, 워크숍 자료, 진단표 |
| 4. 고객 전용 | 공개하지 않음: 테넌트별 구성도, 내보낸 데이터, 보안 예외, 계약 정보 |

## 첫 연락에 넣지 말아야 할 정보 {/* #do-not-include-in-the-first-request */}

- 고객사 법인명
- 테넌트 ID, 도메인 목록, 사용자 목록
- 계약 금액, 할인율, 가격 가정
- 내부 프로젝트 코드명
- 보안 예외 상세
- 실제 IP 대역이나 시스템 이름이 들어간 구성도

업종, 주제, 프로젝트 단계, 필요한 결과물 형태로 대신 알려 주세요.
