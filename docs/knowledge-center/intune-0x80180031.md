# Intune Enrollment Error 0x80180031

## Executive Summary

Microsoft defines `0x80180031` as `MENROLL_E_MDM_NOT_CONFIGURED`: the MDM service is not configured. The code alone does not establish a duplicate device or stale registration problem. See the [Windows MDM error definitions](https://learn.microsoft.com/en-us/windows/win32/mdmreg/mdm-registration-constants).

Start with the enrollment method, tenant MDM configuration and affected user's enrollment scope. Then check licensing and the detailed enrollment event. Device registration cleanup is a separate recovery decision that needs its own evidence.

## 한국어 요약

`0x80180031`의 공식 의미는 **MDM 미구성**입니다. 기존 장치 객체 충돌로 단정하지 말고, 의도한 테넌트와 등록 방식, MDM 설정, 사용자 범위와 라이선스를 먼저 확인하세요.

`dsregcmd /status`는 읽기 전용 상태 확인에 사용합니다. MDM URL이 있어도 실제 Intune 등록을 증명하지 않으므로 Intune 장치 기록과 등록 이벤트를 함께 대조해야 합니다.

Users may observe:

- Enrollment failure
- Device registration failure

## Common Root Causes

The first row is the official error meaning. Other rows are checks for the selected enrollment path, not independently proven causes of every occurrence.

| Check | Interpretation and next action |
|---|---|
| MDM configuration | Confirm the expected tenant has the intended MDM provider configured |
| Automatic enrollment user scope | For automatic enrollment, verify the affected user is included in **Some** or **All**; **None** disables automatic enrollment, not every form of manual enrollment |
| User entitlement | Check an assigned Intune entitlement; automatic MDM enrollment also needs Microsoft Entra ID P1/P2 entitlement |
| Enrollment event | Read the complete event and enrollment restriction details before changing device state |
| Existing registration | Investigate only if independent evidence identifies a conflict; this is not the definition of 0x80180031 |

Use [Windows automatic enrollment](https://learn.microsoft.com/en-us/intune/intune-service/enrollment/windows-enroll) and the [Entra join planning requirements](https://learn.microsoft.com/en-us/entra/identity/devices/device-join-plan) for scope, entitlement and MDM URL settings. Apply the requirements for the actual enrollment method, rather than enabling automatic enrollment tenant-wide as a blanket fix.

## Diagnostic Commands

```powershell
dsregcmd /status
```

Read the **DeviceManagement-Enterprise-Diagnostics-Provider/Admin** event log around the failure and compare the expected tenant and affected user with the Intune record. See [how to interpret dsregcmd output](https://learn.microsoft.com/en-us/entra/identity/devices/troubleshoot-device-dsregcmd).

- Empty MDM URL fields can mean missing MDM configuration or that the current user is outside enrollment scope.
- Populated MDM URL fields do **not** prove that the device is managed.
- `dsregcmd /leave` changes registration state and is not a diagnostic command or a default fix for this code. Use a separate approved recovery runbook only when a confirmed registration issue requires it, with user access and rejoin recovery planned.

## Decision Checklist

| Decision | Recommended Question |
|---|---|
| Device state | Is the device Microsoft Entra joined, Microsoft Entra hybrid joined or Microsoft Entra registered? |
| MDM configuration | Is the intended MDM provider configured and is the user in the correct scope? |
| Policy block | Are enrollment restrictions blocking the platform or user? |
| Recovery | Does evidence justify a state-changing recovery action, and is a rejoin/access recovery path documented? |
| Support handoff | What evidence should service desk collect before escalation? |

## Common Risks

- Deleting device objects without confirming ownership and impact
- Resetting or leaving the device before confirming MDM configuration and user scope
- Ignoring enrollment restriction policies
- Not documenting the final healthy enrollment state
